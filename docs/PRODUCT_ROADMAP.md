## 1. 产品定位

乡声集盒是“乡声万语”体系面向普通用户的核心入口：让人愿意**听、查、录、分享并留下真实乡音**，同时把可长期保存、可追溯的方言资料沉淀为公共数字基础。

产品同时受两条约束：

1. **先有真实用户价值**：用户首先因为有用、有趣、身份认同、表达、记忆、比较或分享而来，而不是因为“保护方言是一项义务”。
2. **必须可复制到多方言**：Recording 是原始媒体事实；Entry、读音、方言归属和其它语言学解释允许修订与竞争，不把莆仙方言特有字段固化为所有方言的通用真理。

## 2. 当前领域基线

- 新功能只使用 Entry / Recording V2，不恢复 Can / Nameplate / Flavor / Package 作为活动模型。
- Entry 与 Recording 独立存在，通过有角色的关联连接。
- 原始录音、贡献者原话、来源和 Evidence 不被后续整理结果覆盖。
- Dialect 是按需建立的语言变体/使用范围树；父节点声明不自动扩展成所有子节点都成立。
- AI、相似度、点赞、支持数只能提供线索，不能自动裁决唯一正确写法、读音或解释。

## 3. 两条 Contributor Track

两个 Track 共同建设同一仓库，不形成目录或代码所有权边界。

- **Dialect Experience / 乡声共创计划**：普通用户价值、听查录主旅程、分享、贡献反馈、地方站用户体验。
- **Dialect Commons / 方言数字基建计划**：多方言数据模型、Evidence、迁移、检索、数据质量、rights/consent、基础设施。

## 4. 优先级层

### P0 · Core UX & Stability

目标：听 / 查 / 录 / 我四条主任务成立，基础可用性和运行稳定性可持续回归。

长期 UI / IA debt：#339。当前春节 P0/P1：#439 及其 Spring Epic / Leaf。

### P1 · Preservation & Sharing Loop

目标：形成“消费 → 分享/比较 → 新用户进入 → 录音/确认/补充 → 资料变好”的闭环。

重点包括：

- Entry / Recording 分享卡与分享落地；
- “你们那里怎么说”的跨地区比较与低成本反馈；
- 录音提交后的整理状态和知识影响反馈；
- 兴化语记迁移为莆仙方言旗舰站；
- 旧入口、旧链接、账号与资料迁移的连续体验。

### P2 · Community

社区能力服务于资料使用和人与人的真实交流，而不是复制通用社交平台。评论、圈子、消息、挑战等只有在能增强留存、分享或资料贡献时继续扩展。

### P3 · Dialect Infrastructure

重点包括：

- 多方言架构验收；
- 迁移 rehearsal 与数据质量；
- provenance / rights / consent；
- 稳定引用与研究/教育导出；
- 在真实需求驱动下演进 RecordingSegment / Annotation。

### P4 · Intelligence

ASR、相似度、语义检索、自动建议等能力作为**可审计的辅助层**接入，不成为语言事实的自动裁判。

## 5. Planning horizon

P0–P4 是优先级，不等于五个串行阶段。

### 近期 · 0–6 周

> Active Sprint Charter 优先于本节 planning horizon。当前 2027 春节阶段的实际顺序以 #439、W #91 与 Project #7 为准。本节用于 Sprint 外的长期默认优先序，不意味着其中每项都必须在当前 0–6 周实施。

- 收敛 P0 核心 UX；
- 跑通分享 / 比较 / 贡献反馈最小闭环；
- ProductProfile / Hinghwa Station MVP；
- Legacy Cutover ADR、迁移 rehearsal、旧 ID 映射和数据质量基线；
- 多方言架构验收矩阵；
- 建立 AI-native Contributor 门禁与稳定 Ready Queue。

### 中期 · 6 周–4 个月

- 完整跨地区比较体验；
- 挑选并通用化真正有用户价值的 quiz / challenge / memory 类能力；
- 泛化旧语义检索；
- 兴化语记主要数据与入口完成技术 cutover；
- rights/consent、稳定引用与基础导出；
- 第二方言真实试点。

### 远期 · 4–12+ 个月

- 多 Station 可复制运营；
- versioned annotation schema；
- 数据集版本、稳定引用和开放 API；
- 高质量研究/教育导出；
- AI/ASR 作为可审计建议层规模化接入。

每 4–6 周按真实用户反馈、迁移结果和维护者容量重排一次。AI 可以压缩实现时间，不能压缩用户验证、数据核对和隐私决策周期。

## 6. 与兴化语记的关系

“兴化语记”品牌保留，但技术主线并入乡声集盒，成为莆仙方言站点 / 旗舰地方馆。

迁移规则：

- Legacy → 乡声集盒单向迁移，不做双向同步；
- 旧仓库只保留安全、数据完整性、迁移阻塞和严重线上故障修复；
- cutover checklist 完成前不 archive；
- 账号最终迁入乡声集盒统一身份，乡声集盒身份是未来主要登录主体；
- 旧 ID、旧 URL、分享链接、数据来源和 Evidence 必须可追溯。

详见 [兴化语记迁移说明](HINGHWA_STATION_MIGRATION.md)。

## 7. 与万语校坊的关系

万语校坊是相邻的资料智能协同校勘产品，不与乡声集盒强行合并后端。

早期边界固定为：

- **乡声集盒是普通用户与统一身份主入口**；
- 日常轻量补充、确认和高质量成员的普通整理动作，优先在乡声集盒内完成，避免为了一个点击强迫用户跨产品；
- 只有进入“成批材料、独立多人校对、管理员仲裁”等完整校勘工作台时，才进入万语校坊；
- 两端近期不建设实时双向业务同步；资料通过**明确导出 → 人工审核 → 导入**完成交接，并保留 manifest、来源、批次和责任人；
- 后续若建设适配层，也必须保持两个产品的领域边界，不能把内部数据库表互相当公共 API。

## 8. 当前执行原则

早期实行“**数据优先，同时打磨产品闭环**”：数据质量、迁移和可追溯性不等待 UI 全部完成；产品也不等待数据基础设施完美后才验证真实用户价值。

任何新大功能进入开发前都应先回答：

1. 它服务哪个真实用户/数据问题？
2. 属于 Experience 还是 Commons 的主叙事？
3. 是否已有 Issue / PR 可承接？
4. 能否拆成 XS / S / M 的可验证叶子工作包？
5. 是否扩大了 Entry / Recording、身份、迁移或跨产品数据边界？若是，先进入 ADR / needs-spec，而不是直接编码。
